# 飲料點餐系統
用於點選飲料並集中查閱最近訂單（虛構示範，原為報修登記系統）。

需求與待確認事項見 [點餐需求筆記](點餐需求筆記.txt)。`文件/` 內的 Excel、PowerPoint、Word 仍為報修版，尚未改寫。

## 網頁前端

根目錄 `index.html` 為入口，`style.css` 提供手機與桌面樣式，`app.js` 負責驗證、新增及讀取最近 20 筆訂單，`config.js` 放置 Supabase URL 與公開 publishable key。supabase-js v2 由 jsDelivr CDN 載入，無建置步驟。

- 表單欄位：點餐人、飲品（手動輸入，最多 50 字）、糖份（無糖～全糖）、冰量（去冰、微冰、少冰、正常冰、溫、熱）、金額、數量、備註（選填）。
- 金額為每杯價格，依店家實際價目手動輸入（1～9,999 元整數）；數量 1～50 杯。表單即時顯示「小計＝金額 × 數量」。系統不內建價目表，無法確認輸入的金額是否正確。
- 清單：讀取最近 50 杯，依訂單編號分組成訂單卡片，新的在上面，時間以台北時間顯示。每張卡片顯示訂單編號、訂單合計、每杯小計、糖份、冰量、製作狀態與備註；沒有訂單編號的舊資料顯示為「訂單（無編號）」。可依製作狀態「全部、待製作、製作中、已完成」篩選（僅篩選已載入的 50 杯），並顯示目前篩選的訂單數、杯數與合計金額。若一張訂單跨過第 50 杯的界線，較舊的部分不會顯示。
- 一次點多杯：填好一杯後按「＋ 新增下一筆飲品」，這杯會加入「已點飲品」清單（可按「移除」），表單換成「第 N 杯」的新頁面並保留點餐人。全部點完按「完成訂單」，跳出「確認訂單」頁面列出每杯小計並自動加總合計金額；按「確認送出」才寫入資料庫，按「返回修改」可繼續編輯。目前頁面若空白且清單已有飲品，只送出清單內容。一次最多 20 項。畫面見 [確認訂單](docs/order-summary.png)。
- 整張訂單以一次陣列新增送出，資料庫以單一指令寫入，全部成功或全部失敗；送出失敗時保留已點內容，可按「重新送出」。每杯仍是一筆紀錄，同一張訂單共用訂單編號。已點飲品只存在目前頁面，重新載入或關閉後不保留。
- 訂單編號：格式為台北日期 YYMMDD、連字號、4 碼大寫英數（不含 I、O），例如 `261116-7K3P`。開啟「確認訂單」時由瀏覽器產生並顯示，在確認頁內重新送出沿用同一編號；送出成功的訊息也會顯示編號。資料庫只檢查格式，不保證唯一（每天約 100 萬種組合，示範規模下重複機率極低）。
- 前端每杯送出 order_no、customer_name、drink、sugar、ice、amount、quantity、note（未填為 null）；狀態與下單時間由資料庫產生。

本機啟動：在根目錄執行 `python3 -m http.server 8000`，開啟 http://localhost:8000 。語法檢查：`node --check app.js` 與 `node --check config.js`。

## 資料庫

新資料庫執行 `supabase/schema.sql` 建立 `drink_orders` 資料表、權限與 RLS（任何人可新增、讀取，不可修改、刪除）；正式專案已於 2026-11-16 執行，舊的 `repair_requests` 表不受影響。本檔為一次性建表，不可對已存在的資料表重複執行。

之後的變更放在 `supabase/migrations/`，依檔名順序在已建立的資料庫各執行一次：

| 遷移檔 | 內容 |
|---|---|
| `20261116_01_drink_free_text.sql` | 飲品由固定清單改為手動輸入（1～50 字、不可只有空白） |
| `20261116_02_ice_warm.sql` | 冰量新增「溫」 |
| `20261116_03_order_no.sql` | 新增訂單編號 `order_no`（可為空、格式檢查、索引、anon 可寫入） |
請勿在前端放入 secret 或 service_role 金鑰。

## PWA 安裝與離線介面

網頁提供 `manifest.webmanifest`、192／512px 圖示與 `sw.js` Service Worker，可在支援的瀏覽器加入主畫面。正式安裝需 HTTPS（GitHub Pages 已提供）；本機測試可用 `http://localhost`。

- 第一次需連線開啟，Service Worker 快取後才可離線重新開啟介面。離線時停用送出與重新整理，不儲存訂單或表單，也不自動補送。
- 快取僅限此目錄的靜態介面、公開設定、manifest 與圖示；不快取 Supabase API、訂單資料或外部 CDN，也不攔截 POST。修改快取檔案時須遞增 `sw.js` 的 `CACHE_NAME` 版本（目前 `drink-shell` `v3`）；啟用時會清除同範圍舊報修版快取。
- 新版更新提示：部署新版後，已開啟的頁面在背景下載新版，完成後於頁面上方顯示「有新版本可以使用。」與「立即更新」按鈕，不會自動重新載入。按下按鈕才啟用新版並重新載入；若表單已有填寫內容，會先確認是否放棄。回到頁面時也會檢查是否有新版。若新版已由其他分頁啟用，提示改為「新版本已在其他分頁啟用。」，按鈕直接重新載入。畫面見 [更新提示](docs/update-banner.png)。
- 已停留在舊版（v1 以前）的瀏覽器沒有這個提示，需要關閉此網站的所有分頁（已安裝的 App 需從多工畫面關閉）後重新開啟，才會換成新版；之後的更新即會顯示提示。

## 驗證

執行 `node --check app.js`、`node --check pwa.js`、`node --check sw.js`，以及 `node tests/pwa.cjs`（需 Playwright 與 Chromium，可用 `CHROMIUM_PATH` 指定）。測試以虛構 API 驗證 manifest、Service Worker、離線重新載入、狀態篩選與合計金額、金額與數量驗證、送出欄位、錯誤提示及無自動補送。手機截圖見 [預覽](docs/mobile-preview.png) 與 [離線畫面](docs/pwa-mobile-offline.png)，皆為虛構資料。實際 Android／iOS 安裝仍需在裝置上確認。
